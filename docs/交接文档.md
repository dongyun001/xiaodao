> **用途**：接手的人（开发 / 运维 / 辅导员团队）先读这一份，了解"现在是什么状态、怎么跑起来、还差什么"。

> 本文不含任何真实凭据，只写变量名。

## 1. 项目是什么

面向高校学生的辅导员问答服务。学生通过微信公众号提问校内制度类问题，系统基于**新知识库**和**学校官网公开通知**给出带出处的回答；命中危机关键词或应急场景时走固定话术并通知辅导员。

**明确不做**：不登录学校系统、不抓取非公开页面、不存储个人凭据；不做持续对话式心理咨询 / 诊断 / 用药建议（负面情绪只做 1~2 句共情 + 转介）；本期不做多轮上下文、语音识别、转人工、办事流程指引。

## 3. 技术栈与目录

Python 3.11 + FastAPI + SQLAlchemy 2.0 + PostgreSQL 15+/pgvector + Alembic + APScheduler + wechatpy；LLM 用 DeepSeek（OpenAI 兼容），Embedding 走任意 OpenAI 兼容服务（默认 SiliconFlow `bge-m3`，本地可用 Ollama `qwen3-embedding:4b`）。

目录与各文件职责见 `README.md`「目录结构」与「架构简图」。

## 4. 本地跑起来

```bash
cp .env.example .env          # 然后按第 5 节填写；不要把 .env 提交
docker compose up -d --build  # postgres + app，容器启动时自动 alembic upgrade head
curl http://localhost:8081/api/health   # 期望 OK

# 样例数据（可选，用于冒烟）
python scripts/ingest_knowledge.py --input data/knowledge --dry-run
python scripts/ingest_knowledge.py --input data/knowledge
python scripts/fetch_notices.py --once --dry-run --pages 1
python scripts/fetch_notices.py --once --pages 1

pytest -q
ruff check . && ruff format --check .
```

不用 Docker 时：先起 PostgreSQL + pgvector，再 `alembic upgrade head`，然后 `uvicorn app.main:app --port 8081`。

## 5. 配置

完整清单与默认值见 `README.md`「环境变量」，模板见 `.env.example`。必须由接手人自己填写、不要从聊天记录或文档里复制：

- 数据库：`DB_PASSWORD`
- LLM：`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`（当前平台可用值：`deepseek-flash`、`deepseek-v4-pro`）
- Embedding：`EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS`（MRL 模型才填）
- 微信：`WECHAT_TOKEN`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`WECHAT_ENCODING_AES_KEY`
- 告警：`DINGTALK_WEBHOOK`、`DINGTALK_SECRET`
- 后台：`ADMIN_USERNAME`、`ADMIN_PASSWORD`（可填 bcrypt 哈希，以 `$2` 开头）
- 采集：`NOTICE_FETCH_BASE_URL`、`NOTICE_FETCH_CRON`

`.env` 权限 600，已 gitignore；容器内访问宿主机服务用 `host.docker.internal`（`127.0.0.1` 在容器里指容器自己）。

## 6. 改代码前必须知道的约定

- **规则链顺序与 `path` 枚举**：只认 `docs/接口契约.md`。危机关键词永远最先判断，且该分支**不得调用 LLM**；检索排在"留空板块"之前。
- **响应字段一律 camelCase**（`docTitle`、`topSimilarity`、`createdAt`…），改字段先改契约文档。
- **`qa_log` 只允许 INSERT 和只读查询**：没有 UPDATE/DELETE 接口或 ORM 写方法。危机告警因此是"**先发告警、再写日志**"。
- **知识库按"条"切分**：条的位置按标题文本（`第X章`/`第X节`/`第X条`）识别，**不限定 `##` 或 `###`**；空正文、认不出条号、manifest 不一致都直接报错。
- **向量维度、embedding 模型与 `vector(N)` 必须一致**；换模型必须新建迁移、重建列与 HNSW 索引、全量重算。
- **词表 / Prompt / 固定话术**都在 `app/resources/*.yml`，不要写进 Python。
- 配置只从环境变量读，入口只有 `app/config.py`。

## 7. 数据流

```text
data/knowledge/*.md + manifest.csv
    └─ scripts/ingest_knowledge.py ──► knowledge_base（每条一个向量）

学校官网「通知公告」
    └─ scripts/fetch_notices.py / APScheduler ──► official_notice（content_hash 去重 + 向量）

学生提问（/api/ask 或微信）
    └─ 规则链 ──► 回答 + qa_log；危机时 ──► 钉钉告警 + qa_log.alert_sent
```

## 8. 运维要点

- 定时采集按 `NOTICE_FETCH_CRON`（5 段，**UTC**）运行；未配置 `NOTICE_FETCH_BASE_URL` 时不启动。
- **多 worker 部署有三个已知问题**：定时采集会重复跑、后台登录锁定失效（进程内计数）、微信长连接/内存状态不共享。上线前要么固定单 worker，要么换成共享存储。
- 迁移随容器启动执行（`alembic upgrade head && uvicorn ...`），迁移失败容器直接退出。
- 应用日志不打印学生原话全文、不打印密钥/webhook；后台列表对 `openid` 掩码。
- `/admin/**` 必须走 HTTPS，建议限校园网/VPN；日志导出或截图需审批。
- 数据库备份、限流防刷、CI/CD、微信回调幂等**尚未实现**（见第 10 节）。

## 9. 接手前需要对方提供

1. 真实《学生手册》Markdown 与 `manifest.csv`（格式见 README「知识库准备」）。
2. 微信测试号或正式公众号的 `WECHAT_TOKEN` / `WECHAT_APP_ID` / `WECHAT_APP_SECRET`（安全模式还要 `WECHAT_ENCODING_AES_KEY`），以及一个**公网可达的 HTTPS** 回调地址。
3. 钉钉机器人 webhook 与加签 secret（机器人安全设置必须是**加签模式**），以及授权群。
4. 服务器、域名与证书；后台的访问范围（校园网 / VPN）。
5. 学校对"留空板块"的菜单口径（现在 `sections.yml` 用的是手册 9 个章节，与微信菜单的"6 板块"对应关系未确认）。

## 10. 已知限制与待办

**P1（上线前必须处理）**

- 微信回调**未用真实公众号报文验证**。踩坑记录里明确写过：AES/签名必须用真实报文实测。
- 钉钉告警**未真实送达验证**；测试接口已挪到 `/admin/api/alert/test` 并加 Basic 认证。
- 多 worker 下的调度重复与登录锁定失效（见第 8 节）。
- `RETRIEVAL_MIN_SCORE` 目前是 `0.48`，是在 5 条样例条款上用 `qwen3-embedding:4b` 标的；**真实手册入库后必须重新标定**。
- 关键词检索路对中文自然问句几乎不命中（整句无空格、顿号 `、` 不在切分集内），实际召回主要靠向量。
- `app/resources/` 里的**危机词表、排除词表、敏感词表都是占位内容**，必须按真实语料补充；敏感词策略（只记录不拦截）仍需产品确认。
- 管理后台尚无速率限制；告警接口虽然加了 Basic，仍需确认是否需要额外限制。

**P2（可以后补）**

- 通知命中时 `sources[]` 没有 url 字段可放（契约缺口，建议加 `sourceType` / `docUrl`）。
- `qa_log.need_type` 列已建但取值未定义，当前写 `null`。
- `intent_normalize_failed` 在 `path` 枚举里但实际不会返回（归一化失败即降级继续）。
- CI/CD、数据库定时备份、微信回调幂等、后台 HTTPS 终结均未实现。
