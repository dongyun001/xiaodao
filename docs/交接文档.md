## 1. 一句话

学生通过微信公众号或 `POST /api/ask` 提问校内制度类问题；服务检索「知识库条款 + 官网公开通知」，按固定规则链决定回答方式，响应带出处，全程写 `qa_log`；命中危机关键词时走固定话术并触发钉钉告警。

## 2. 运行拓扑

```text
微信用户 / 调用方
   │  GET|POST /wechat/callback        POST /api/ask
   ▼
FastAPI (uvicorn, :8081)
   ├─ 规则链 qa_service         ──► PostgreSQL + pgvector（knowledge_base / official_notice / qa_log）
   ├─ 检索 rag_service          ──► Embedding 服务（OpenAI 兼容：SiliconFlow 或本地 Ollama）
   ├─ 生成 llm_service          ──► DeepSeek（OpenAI 兼容 /chat/completions）
   ├─ 通知采集 notice_fetch     ──► 学校官网公开页面（httpx + BeautifulSoup）
   ├─ 告警 alert_service        ──► 钉钉机器人（加签）
   └─ 管理后台 /admin/**        ──► 同一 PostgreSQL（只读查询 + 统计）
APScheduler（进程内）按 NOTICE_FETCH_CRON 定时触发通知采集。
```

## 4. 数据模型

三张表，结构见 `docs/数据库.md`。要点：

- `knowledge_base.id` = `doc_key:chapter:article_num`（`doc_key` 是 `doc_num`，缺省用文件名）；重复入库按 `id` upsert。
- `official_notice.content_hash` = 正文去空白后的 SHA-256，唯一；重复采集不新增。
- `qa_log` 只 INSERT；`alert_sent` 在写入前确定（告警先发、后写日志）；`openid` 在后台列表里掩码。
- 三个 `embedding` 列都是 `vector(1024)`，各带一个 HNSW cosine 索引；`qa_log` 无向量列。

## 6. 规则链（当前实现顺序）

`qa_service._run_chain()`，命中即返回：

1. **危机关键词**命中且未命中排除词 → `crisis`（固定话术 + `is_high_risk=true`；**不调用 LLM**）
2. **意图归一化**（`INTENT_DEEPSEEK_TIMEOUT`，失败降级继续）
3. `emotion=emergency` 且命中排除词 → 降级 `normal`
4. `emotion=emergency` 命中场景 → `emergency`；未命中 → `generic_emergency`
5. `urgency=high` → `generic_emergency`
6. `emotion=venting` → 只共情，截断 250 字 → `negative_emotion_venting`；`emotion=consult` → 先共情，继续往下
7. **检索**：知识库混合检索 + 通知向量检索；通知条件满足 → `notice`
8. 知识库 top1 ≥ `RETRIEVAL_MIN_SCORE` → 生成回答 → `normal`（`consult` 时为 `negative_emotion`）
9. 两条路都无依据：所属板块在库中为空 → `empty_section`；否则 → `low_relevance`
10. 边界异常 → `error`

进入 `qa_log` 前，若 `is_high_risk` 则先发钉钉告警并把结果写入 `alert_sent`。

## 7. 检索实现与常数

- 向量：`topK * 2` 条余弦最近邻。
- 关键词：按 `[，。！？?,!\s]+` 切分；长度 ≥ 2；去 `stopwords.yml`；去重；最多 8 个；每个词对 `content` 做 `ILIKE`，最多 5 条。
- 融合：仅关键词命中记 `0.35`；同时命中记 `min(0.95, 向量分 + 0.08)`；仅向量保留原分；按分数降序取 `topK`。
- 通知路由：`noticePreferred = intent 含"通知" 或 问题含"什么时候开始/截止时间/通知/公告/公示/发布/公布/安排"`；`noticeHigher = 通知 top1 > 知识库 top1`；`noticeValid = 通知 top1 ≥ NOTICE_RETRIEVAL_MIN_SCORE`；`noticeSoftValid = 通知 top1 ≥ 0.30`；`(preferred && softValid) || (higher && valid)` → `notice`。
- 告警：超时 5 秒；同 `openid` 在 `ALERT_DEDUP_MINUTES` 内已有 `is_high_risk && alert_sent` 记录则抑制；无 `openid` 不去重。
- 后台：登录失败 5 次 / 10 分钟锁定（进程内计数）；`openid` 掩码保留前 4 后 2。
- 微信：客服消息按 UTF-8 字节分段，上限 1900，多段加 `(n/m)` 前缀，段间隔 0.3 秒。

## 9. 外部依赖的降级行为

| 依赖 | 失败时 |
|---|---|
| DeepSeek（意图/生成/共情） | `LLMError` → 规则链边界降级为 `error` 固定话术；意图失败则用 fallback 继续 |
| Embedding | `EmbeddingError` → `error` 固定话术；通知采集时整体失败退出 |
| 钉钉 | 只记 warning，学生回复照常，`alert_sent=false` |
| 微信客服消息 | 未配置 `WECHAT_APP_SECRET` 时跳过并记日志；发送异常只记日志 |
| 学校官网 | 采集失败抛 `NoticeFetchError`；定时任务只记日志，手动触发返回 502 |

## 10. 日志与隐私（当前实现）

- 不打印密钥、webhook、AES key、完整向量、待嵌入文本、学生原话全文。
- `qa_log` 存 `question` 原文（授权人员可查）；后台列表返回完整 `question`、掩码 `openid`，无导出接口。
- 告警文案含 `openid` 与学生原话截断片段（50 字），发往授权群。
- 应用日志里 embedding/LLM 只记条数、维度、耗时类信息。

- `Dockerfile`：python:3.11-slim，启动 `alembic upgrade head && exec uvicorn ...`，自带 HEALTHCHECK。

## 13. 当前状态的事实

- 微信回调、钉钉告警的代码路径已实现；**尚未用真实公众号报文、真实钉钉 webhook 验证**。
- `app/resources/` 里的危机词、排除词、敏感词、应急场景、菜单话术为**占位内容**。
- 本地 `.env` 的 `RETRIEVAL_MIN_SCORE` 为 `0.48`（针对当前 embedding 模型与样例条款实测）；代码默认值是 `0.55`。
- 当前知识库为 `data/knowledge/` 下的样例条款（5 条），通知来自官网第 1 页（10 条）。
- 定时采集与后台登录锁定都依赖进程内状态，单进程部署下行为与文档一致。
