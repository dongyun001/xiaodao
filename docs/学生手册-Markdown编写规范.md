# 学生手册 Markdown 编写规范

> 本文件以学校提供的《学生手册-Markdown编写规范》为准；第 7 节是仓库侧补充的入库要求（非学校原文），两边冲突时以第 7 节的入库约束为准。

# 1. 文件组织

**一章一个 `.md` 文件。**

```
docs/
├── 01-总则.md
├── 02-学业教务.md
├── 03-奖助评优.md
├── 04-考勤请假.md
├── 05-宿舍管理.md
├── 06-心理健康.md
├── 07-就业毕业.md
├── 08-安全应急.md
└── 09-日常事务.md
```

**为什么一章一文件：**

- 文件小，好阅读、好维护
- 版本对比（diff）清晰，改哪章一目了然
- 每个文件的元信息独立、干净
- 切分时，"一个文件 = 一章"是最简单的对应关系

# 2. 模板

把下面这段完整照抄，替换内容即可。

> **front matter（`---` 里的 title / version）可要可不要**：切分器不从它取信息，章名一律来自 `#` 标题；保留它只用于记录文档名和版本，不需要的话整块删掉即可，不影响切分。

````markdown
---
title: 第三章 奖助评优
version: 2026-10
---


# 第三章　奖助评优

## 第三节　奖学金评定

### 第二十五条

正文

### 第二十六条

正文

### 第二十七条

正文
````

# 3. 规定

## 规定 1：层级固定

- `#` = 章
- `##` = 节
- `###` = 条
- **一个文件只能有一个 `#`**

✅ 正确：

```markdown
# 第三章　奖助评优

## 第三节　奖学金评定

### 第二十五条
```

❌ 错误（层级混乱，程序无法判断哪个是章、哪个是条）：

```markdown
## 第三章　奖助评优

### 第三节　奖学金评定

#### 第二十五条
```

## 规定 2：条号必须独立成标题

条号单独写在一个 `###` 标题里，**正文另起一行**。

✅ 正确：

```markdown
### 第二十五条

正文
```

❌ 错误（条号和正文混在一行，程序还要二次拆分，容易出错）：

```markdown
### 第二十五条 正文
```

## 规定 3：编号统一

全文一律使用 **"第X章 / 第X节 / 第X条"**（中文数字），**不要**混用 `一、`、`1.`、`（一）` 等其他编号方式。

✅ 正确：

```markdown
### 第二十五条
### 第二十六条
```

❌ 错误（同一篇里编号风格不一致，正则和解析都会翻车）：

```markdown
### 第二十五条
### 26.
### （二十七）
```

# 4. 可选项

- **交叉引用写条号**：正文写"详见第二十六条"，不要写"详见上文"——将来做条款关联时有用。
- **一条只讲一个主题**：别让一个"条"跨越两个主题，否则切分后一个 chunk 混两种意思，检索会糊。
- **章末可选 FAQ**：如果本章有高频问答，可以在末尾加一节：

  ```markdown
  ## 常见问答

  ### 问：奖学金什么时候发？
  答：……
  ```

- **图片用相对路径 + 替代文字**：

  ```markdown
  ![奖学金申请流程图](images/scholarship-flow.png)
  ```

# 5. 切分器如何消费这个模板

```
读取单个 .md 文件
  ↓
（可选）解析 front matter → 得到 {title, version}，不参与切分
  ↓
遍历文档中的 ### 标题（每个 ### 就是一个"条"）
  ↓
每个 ### 生成一个 chunk：
   正文   = 该 ### 标题下的全部内容
   metadata = {
       "source"  : 文件名,
       "chapter" : 该 ### 所属的 # 标题,
       "section" : 该 ### 所属的 ## 标题,
       "article" : ### 标题（条号）
   }
  ↓
用 embedding 模型把 chunk 正文向量化
  ↓
写入向量库（向量 + 正文 + metadata）
```

# 6. 命名与版本约定

- 文件名：`编号-板块名.md`，如 `03-奖助评优.md`
- 编号与章号对应，两位数字补零（`01`、`02`……）
- 内容有修订时更新 front matter 里的 `version` 字段，格式 `YYYY-MM`

# 7. 仓库侧入库附加要求（非学校原文）

本项目用 `scripts/ingest_knowledge.py` 入库，除了上面的编写规范，还必须满足：

1. **每个 `.md` 都要登记到 `manifest.csv`**，文件名与 `file` 列完全一致；多一个、少一个都会报错停止。
2. **`doc_title` 与 `category` 必填**：由 `manifest.csv` 提供，或在文件 front matter 写 `doc_title` / `category`。规范第 2 节的 `title` / `version` 不会被入库脚本读取，只作记录。
3. **`doc_num` 约定**：同一本学生手册的 9 个章文件在 manifest 里使用相同的 `doc_num` 与 `doc_title`；独立规定（如单项管理办法）各自单独编号。`id` 由 `doc_num + chapter + article_num` 生成，同一手册内不会冲突。
4. **章末 FAQ 暂不入库**：`## 常见问答` 与 `### 问：…` 不是“条”，入库时只记 warning 并忽略；写在条中间还会被并进上一条正文。FAQ 需要进入检索时，请改成 `### 第N条` 形式的条款，或先与开发确认。
5. **图片按纯文本处理**：`![说明](路径)` 这一行会原样存进条款正文，不会被解析成图片。非必要不要在条款里放图片。
6. **入库前先 dry-run**：`python scripts/ingest_knowledge.py --input data/knowledge --dry-run`，确认文件数、条数、warning 后再正式入库。
7. **独立规定（非手册章文件）**：没有章结构时，在 front matter 写 `chapter: <规定名称>`，不要硬造 `# 第X章` 标题；此时章名以 front matter 为准。手册章文件仍按下文规范用 `#` 标题给出章名。
