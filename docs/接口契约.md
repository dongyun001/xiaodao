# 接口契约

> **用途**：`POST /api/ask` 规则链、响应字段与管理后台分页的详细契约。`AGENTS.md` 只保留优先级结论，细节以本文件为准；实现与本文件不一致时，先改契约再改代码。
>
> **状态**：当前代码尚未实现，本文件描述目标契约。对外字段一律 camelCase。

## 1. 规则链

`POST /api/ask` 严格按序执行，命中即返回，不得跳步。

| 顺序 | 条件 | 处理 | `path` |
|---|---|---|---|
| 0 | `question` 为空 | 直接返回固定话术 | `empty_question` |
| 1 | 危机关键词命中且未命中排除词 | 固定话术 + 高危日志 + 异步告警；**此前不得调用 LLM** | `crisis` |
| 2 | 意图归一化（超时 10s） | 失败降级 `IntentResult.fallback`，用原问题继续，不报错给学生 | 由后续分支决定 |
| 3 | `emotion=emergency` 且命中排除词 | 降级为 `normal` 继续 | 由后续分支决定 |
| 3 | `emotion=emergency` 命中场景 | 场景固定话术 | `emergency` |
| 3 | `emotion=emergency` 未命中场景 | 通用应急话术 | `generic_emergency` |
| 4 | `urgency=high` | 通用应急话术 | `generic_emergency` |
| 5 | 负面情绪 `venting` | 共情 Prompt + 250 字截断 | `negative_emotion_venting` |
| 5 | 负面情绪 `consult` | 先共情，再走检索 | `negative_emotion` |
| 6 | RAG 混合检索（知识库 + 官网通知）+ 通知路由 | 命中通知则据此回答 | `notice` |
| 7 | 知识库 top1 ≥ `RETRIEVAL_MIN_SCORE` | 正常生成 | `normal` |
| 8 | 两条路都无依据，且问题所属板块在库中为空 | 板块引导话术 | `empty_section` |
| 9 | 两条路都无依据，板块不为空 | 拒答 | `low_relevance` |
| — | 边界异常 | 降级为稳定话术，不透传堆栈 | `error` |

**优先级**：危机关键词 > `emergency` > `urgency=high` > 负面情绪（`venting`/`consult`）> RAG（通知 / 知识库）> 留空板块 > 低相关度拒答。危机判断永远优先，不得把危机词交给模型判断。

**为什么检索排在留空板块之前**：库里没有条款的板块，官网通知可能正好有依据；先判空板块会把通知分支挡死。实测「心理健康教育宣传周活动的通知」通知命中 0.6968，若先判空板块就只会返回"该板块暂未公布"。

**留空板块判定**：先检索；知识库与通知都没有依据时，若问题被归入 `app/resources/sections.yml` 里声明的板块、且该板块在 `knowledge_base` 中没有任何条款 → `empty_section`。`section=None`（问题不属于任何声明板块）走 `low_relevance`。

**排除词**（`app/resources/exclusion-words.yml`）同时作用于第 1 步和第 3 步：命中危机关键词但含排除词时不算危机；`emotion=emergency` 但含排除词时降级为 `normal`。

**优先级**：危机关键词 > `emergency` > `urgency=high` > 负面情绪（`venting`/`consult`）> RAG（通知 / 知识库）> 留空板块 > 低相关度拒答。危机判断永远优先，不得把危机词交给模型判断。

**通知分支**：命中以下任一条件时走通知答案，`path=notice`：

```text
(noticePreferred && noticeSoftValid >= 0.30) || (noticeHigher && noticeValid >= 0.55)
```

### 1.1 `path` 枚举

仅允许：`normal`、`notice`、`crisis`、`empty_section`、`low_relevance`、`emergency`、`negative_emotion`、`negative_emotion_venting`、`generic_emergency`、`intent_normalize_failed`、`empty_question`、`error`。

- 拒答率统计计入 `low_relevance`、`empty_section`、`intent_normalize_failed`；`fallback` 是话术，不是 `path`。
- `normal` 表示命中知识库条款，`notice` 表示命中官网通知，两者不混用。

### 1.2 待确认

- `intent_normalize_failed` 仍在枚举与统计口径里，但规则链第 2 步失败时按“降级继续”处理，没有独立出口。实际实现从不返回该 path，触发条件待确认。
- **通知的来源链接没有位置安放**：`sources[]` 只有 `docTitle` / `chapter` / `articleNum` / `articleTitle` / `content` / `similarity`，没有 url。当前实现把通知映射成 `docTitle=通知标题`、`chapter=null`、`articleNum=""`，链接被丢掉。建议加 `sourceType` 与 `docUrl` 两个字段，改前先定契约。
- **板块口径待确认**：`app/resources/sections.yml` 用的是《学生手册》9 个章节，而微信菜单是“6 板块 + PSYCHOLOGY + CONTACT”，两者对应关系文档里没有写明。菜单落地（步骤 6）前需学校确认。
- `need_type` 列已建，但取值集合没有定义，当前实现一律写 `null`。
- **`consult` 分支的拒答行为**：`consult` 检索不到依据时，当前实现只返回共情话术、不追加“没有依据”的机械拒答（`path` 仍为 `negative_emotion`）。这是实现解读，待确认。

## 2. 字段契约

| 字段 | 位置 | 说明 |
|---|---|---|
| `question` | 请求/响应 | 学生原问题 |
| `answer` | 响应 | 回答或固定话术 |
| `path` | 响应 | 必须落在 §1.1 枚举内，不可为空 |
| `sources` | 响应 | 命中条款列表，可为空数组 |
| `topSimilarity` | 响应 | top1 相似度 |
| `docTitle` | `sources[]` | 文档标题 |
| `chapter` | `sources[]` | 章 |
| `articleNum` | `sources[]` | 条号 |
| `articleTitle` | `sources[]` | 条标题，可为空字符串（条号单独成标题时） |
| `content` | `sources[]` | 条款原文 |
| `similarity` | `sources[]` | 该条相似度 |
| `generatedAnswer` | 日志/后台 | 模型生成内容 |
| `createdAt` | 日志/后台 | UTC 存储，按配置时区展示 |
| `alertSent` | 日志/后台 | 仅告警发送成功后为 `true` |

空问题固定返回：

```json
{"question":"","answer":"请提出你的问题","path":"empty_question"}
```

Pydantic v2 统一配置：`alias_generator=to_camel`、`populate_by_name=True`；序列化用 `model_dump(by_alias=True)`，校验用 `model_validate`。禁止输出 snake_case，禁止 `.dict()`、`.json()`、`parse_obj`。

`/api/ask` 完整响应示例见 `README.md` 的「API 概览」。

## 3. 管理后台分页

- 返回字段：`content`、`totalElements`、`totalPages`、`number`、`size`；`number` 从 **0** 开始。
- 行字段（camelCase）：`id`、`createdAt`、`path`、`intent`、`emotion`、`urgency`、`openidMasked`、`question`、`generatedAnswer`、`topSimilarity`、`isHighRisk`、`sensitiveWordsHit`、`filterResult`、`alertSent`。
- `openidMasked` 是掩码值（保留前 4 位与后 2 位）；`question` 返回完整原话，仅授权人员可查，导出或截图需审批。
- 日志按 `created_at DESC` 排序，同一时间按 `id` 兜底。
- 查询参数：`startDate`、`endDate`（`YYYY-MM-DD`，按 UTC 解释，结束日期含当天）、`path`、`emotion`、`keyword`（对 `question` 参数化 ILIKE）、`page`、`size`（默认 20，上限 100）；不得支持任意 SQL。
- `/admin/**` 使用 HTTP Basic；认证失败 5 次 / 10 分钟锁定（**进程内计数，多 worker 下失效**），锁定返回 429。
- `POST /admin/api/fetch-notices`：手动触发通知采集，参数 `pages`（0 表示用配置值）；采集失败返回 **502** 与 `implemented=true` 的错误说明，不伪造成功。
- `POST /admin/api/alert/test`：告警测试，需 Basic 认证；**不参与去重、不写 `qa_log`**；未配置 webhook 时返回 HTTP 200 且 `success=false`。

## 4. `qa_log` 写入契约

- 只允许 INSERT 和只读查询；禁止 UPDATE/DELETE 接口、后台按钮和 ORM 写方法。
- 每次问答必写一条日志；`path` 非空；`filter_result` 默认 `pass`。
- 危机记录 `is_high_risk=true`；`alert_sent` 只在发送成功后为 `true`，被去重抑制时保持 `false`。
- **告警在写日志之前发送**：因为不允许 UPDATE，`alert_sent` 必须在 INSERT 时就确定。发送失败或被去重时 `alert_sent=false`，学生回复不受影响。
- **去重靠 `qa_log` 只读查询**：同 `openid` 在 `ALERT_DEDUP_MINUTES` 内已有 `is_high_risk=true 且 alert_sent=true` 的记录则抑制。没有 `openid`（如 `/api/ask`）时不去重。
- `POST /api/alert/test` 不写 `qa_log`，也不参与去重。
- `openid` 仅用于告警去重与追溯；应用日志与后台列表必须掩码或哈希。
- 日志不得包含学生原话全文；webhook、token、密钥永不写入日志。
- 告警按既定模板发送（含 `openid`），且只发授权群。
